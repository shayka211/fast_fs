# ucx-sys

Raw FFI bindings to UCX (`ucp` and `ucs`), generated by [bindgen] at build time from
`ucp/api/ucp.h`. There's no safe API here; use the `ucx` crate. Nothing in this crate is
written by hand except `build.rs`, `wrapper.h`, and a 16-line `lib.rs`.

[bindgen]: https://rust-lang.github.io/rust-bindgen/

## Finding UCX

`build.rs` never builds UCX; it only *locates* an install, in this order:

1. **`$UCX_DIR`**: any prefix containing `include/ucp/api/ucp.h` and `lib/libucp.so`.
2. **`<workspace>/.ucx/release`**: built from the `ucx/` submodule by
   `scripts/build-ucx.sh release`. This is the normal setup.
3. **pkg-config `ucx` ≥ 1.12**: a system package.

It then links `libucp` and `libucs` dynamically. UCX loads its transports (shared memory,
cma, tcp, ib) as plugins at runtime, so dynamic linking is the natural mode. It also has no
call overhead: an FFI call is a plain C function call.

At runtime the dynamic loader finds the library through the RUNPATH that
`.cargo/config.toml` embeds (`$ORIGIN/../../.ucx/release/lib`). To use a different build,
for example the debug flavor with UCX's internal assertions and trace logs, override it:

```sh
scripts/build-ucx.sh debug
LD_LIBRARY_PATH=$PWD/.ucx/debug/lib cargo run ...
```

## What bindgen can't do

bindgen translates declarations, not code, so two kinds of UCX API are missing and are
re-implemented in the `ucx` crate:

| Missing | Why | Replacement in `ucx` |
|---|---|---|
| `ucp_init()` | it is `static inline` | calls `ucp_init_version(UCP_API_MAJOR, UCP_API_MINOR, ..)` directly |
| `UCS_PTR_IS_ERR`, `UCS_PTR_STATUS`, ... | function-like macros | `StatusPtr::decode` in `status.rs` |

## Generation settings

- Allowlist: `ucp_*` / `ucs_*` functions and types, `UCP_*` / `UCS_*` constants.
- C enums become plain constants (`UCS_OK`, `UCP_FEATURE_AM`, ...), without enum-name
  prefixes. These enums are used as bit flags, and an unknown value arriving from C into a
  Rust `enum` would be undefined behavior.
- `Default` is derived for structs, so params can be built as `ucp_xxx_t { field, ..Default::default() }`.
- Doctests are off: UCX's C doc comments contain C code blocks that rustdoc would try to
  compile as Rust.

## Updating UCX

Bump the submodule, rerun `scripts/build-ucx.sh release`, then `cargo build`. The bindings
regenerate automatically. The `ucx` crate's `runtime_matches_compiled_api` test catches a
header/library version mismatch.
